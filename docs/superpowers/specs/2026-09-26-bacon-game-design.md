## 1. 개요

정장을 입은 주인공 **베이컨**이 횡스크롤 맵을 점프로 헤쳐나가, 스테이지 끝 벽에 붙어
입을 벌리고 있는 **팩맨** 안으로 쏙 들어가면 클리어되는 오토러너 게임.
스테이지 1~5, 각 1~2분 분량.

초등학생 아이와 함께 만드는 게임이며, 아이가 그린 컨셉 그림 4장이 `image/`에 있다.
아이 그림은 **참고용으로 보존**하고, 실제 화면은 전부 캔버스 코드로 그린다.

### 아이 그림 → 게임 요소

| 파일 | 내용 | 게임에서 |
|---|---|---|
| `image/bacon.jpg` | 갈색 머리, 하얀 사각 얼굴에 점 눈 두 개 + 미소, 검은 정장, 파란 넥타이, 검은 다리 | 주인공 |
| `image/bagoom.jpg` | 갈색 삼각 몸통, 큰 눈 두 개, 가는 다리 + 동그란 발 | 적 |
| `image/background.jpg` | 파란 하늘 + 해, 초록 잔디, 침엽수 / 주황 지붕 토관 / 벽돌 기둥 / 덤불 | 배경 + 장애물 4종 |
| `image/pacman.jpg` | 왼쪽으로 입을 벌린 노란 원, 점 눈 두 개 | 스테이지 골인 지점 |

### 기술 제약

- 순수 HTML5 + JavaScript (ES modules). 빌드 도구 없음, 외부 라이브러리 없음
- 단일 `<canvas>` 2D 렌더링
- PC 웹 + 모바일 모두 지원. 모바일은 **플레이 도중 세로/가로 회전해도 게임이 끊기지 않아야** 한다
- 외부 오디오 파일 없음 — BGM·효과음 전부 Web Audio로 실시간 합성
- 총 에셋 용량 0 (아이 원본 그림은 README용으로만 사용)

## 2. 핵심 게임 규칙

### 2.1 오토러너 + 밀림 판정

베이컨은 화면 왼쪽 30% 지점에 있고, 월드가 왼쪽으로 흘러온다. **조작은 점프 하나뿐.**

장애물 옆면에 부딪히면 즉사가 아니라 **스크롤에 밀려 뒤로 간다.** 화면 왼쪽 끝
(카메라 좌측 + 20u)까지 밀리면 그때 사망. 밀리는 동안 다시 점프해서 탈출할 수 있다.

바굼은 다르다:

- **위에서 밟으면** 바굼이 납작해지며 사라지고, 베이컨은 작게 튕겨 오른다 (+100점)
- **옆이나 아래로 닿으면** 즉시 사망

### 2.2 목숨과 부활

- 목숨 3개. 좌상단에 하트 아이콘 3개, 소모될 때마다 1개씩 줄어든다
- 사망 → **죽은 지점에서 8초 분량 뒤**에서 재개. 그 지점이 장애물이나 바굼과
  겹치면 겹치지 않을 때까지 더 물러난다 (여유 60u)
- 부활 후 **2초 무적 + 초당 7회 깜빡임**. 깜빡임은 보였다 안 보였다 해야 무적인 게 눈에 띈다

**되감기는 거리가 아니라 시간으로 잡는다.** 고정 거리로 하면 스크롤이 빠른 뒷
스테이지일수록 되감기는 시간이 짧아져, 정작 어려운 스테이지에서 되돌아가는 맛이 사라진다.

| 스테이지 | 속도 | 고정 1,200u였다면 | 8초 고정 |
|---|---|---|---|
| 1 | 220 u/s | 5.5초 | 1,760u |
| 2 | 260 u/s | 4.6초 | 2,080u |
| 3 | 300 u/s | 4.0초 | 2,400u |
| 4 | 340 u/s | 3.5초 | 2,720u |
| 5 | 380 u/s | 3.2초 | 3,040u |
- **목숨 0 → 현재 스테이지를 처음부터.** 목숨 3개 복구, 스테이지 점수 0으로 초기화
  (이전 스테이지까지의 총점은 유지). **장애물 배치는 시드를 유지해 그대로 둔다**

### 2.3 점수

| 항목 | 점수 |
|---|---|
| 바굼 처치 | 개당 100 |
| 스테이지 도착 보너스 | 500 |
| 남은 목숨 보너스 | 개당 200 |

별 등급은 스테이지 클리어 시점의 남은 목숨으로 결정: 3개 = ★★★, 2개 = ★★, 1개 = ★

스테이지 결과 화면 예시:

```
── STAGE 1 CLEAR ──

    ★ ★ ☆

 바굼 처치   3 × 100 =  300
 도착 보너스        =  500
 남은 목숨   2 × 200 =  400
 ──────────────────
 스테이지 점수     1,200
 총점                1,200
```

## 3. 좌표계와 화면 대응

### 3.1 월드 단위

게임 로직은 전부 **월드 유닛(u)** 으로 계산하고, 렌더 직전에 한 번만 픽셀로 환산한다.
이 분리가 세로/가로 대응의 전부다.

- `SIGHT_W = 900` — 가로로 항상 보이는 거리 (고정)
- `MIN_VIEW_H = 460` — 세로로 최소한 보여야 하는 높이

`MIN_VIEW_H`는 점프 최고점에서 베이컨 머리가 화면 밖으로 나가지 않는 최솟값이다.
지면 위로 필요한 높이는 `점프 224u + 베이컨 키 100u = 324u`, 여기에 지면 아래 여백
(3.3의 하한 90u)과 머리 위 여유를 더해 460u로 잡았다.

### 3.2 스케일 계산

```
scale   = min(canvasW / SIGHT_W, canvasH / MIN_VIEW_H)   // px per unit
viewW   = canvasW / scale                                 // 실제 보이는 가로 유닛
viewH   = canvasH / scale                                 // 실제 보이는 세로 유닛
```

`min`을 쓰므로 어떤 화면에서도 가로 900u 이상, 세로 460u 이상이 항상 보인다.

| 화면 | scale | 보이는 가로 | 보이는 세로 | 베이컨(100u) 화면 크기 |
|---|---|---|---|---|
| 데스크톱 1600×900 | 1.78 | 900u | 506u | 178px |
| 폰 가로 844×390 | 0.848 | 995u | 460u | 85px |
| 폰 세로 390×844 | 0.433 | 900u | 1950u | 43px |

폰 가로처럼 납작한 화면에서는 세로 제약이 걸려 가로가 900u보다 넓게 보인다
(장애물이 조금 더 일찍 보여 아주 약간 쉬워진다). 반대는 없다 — 900u보다 좁게는 절대 안 보인다.

세로에서는 캐릭터가 작아지는 대신 **장애물이 나타나는 타이밍이 가로와 완전히 동일**하다.
남는 세로 공간은 하늘(해·구름)과 땅으로 채운다.

### 3.3 지면선 배치

가로에서는 지면 윗면을 화면 하단에서 `clamp(viewH * 0.22, 90, 150)` 유닛 위에 둔다.

그런데 세로에서 그 규칙을 그대로 쓰면 지면이 150u에 걸려 **액션이 화면 맨 아래에
깔려버린다.** 그래서 화면이 세로로 길어질수록 지면을 `tallMax = 450u`까지 끌어올려
잔디밭이 화면을 받치게 한다.

```
tallness = viewH / viewW
t        = clamp((tallness - 0.75) / (1.0 - 0.75), 0, 1)
지면높이  = lerp(clamp(viewH * 0.22, 90, 150), 450, t)
지면높이  = min(지면높이, viewH - ACTION_BAND)   // 머리가 잘리지 않게 하는 안전장치
```

보간이라 창을 천천히 줄여도 지면이 툭 튀지 않는다. 마지막 줄은 지면 위로
`ACTION_BAND`(324u)가 반드시 남게 하는 보험이다 — 지금 수치로는 걸리지 않지만,
tallMax를 더 올리면 그때부터 이게 막는다.

| 화면 | 지면 높이 | 지면 위 여유 | 잔디밭 |
|---|---|---|---|
| 데스크톱 1600×900 | 111u | 395u | 198px |
| 폰 가로 844×390 | 101u | 359u | 86px |
| 폰 세로 390×844 | **450u** | 1498u | 195px |
| 태블릿 세로 820×1180 | **450u** | 845u | 410px |

잔디밭에는 꽃을 흩뿌린다. 아래쪽 줄일수록 크고 조금 빨리 흘러 앞에 있는 것처럼 보인다.
위치는 월드 좌표 해시로 정하므로 카메라가 움직여도 깜빡이거나 자리를 옮기지 않는다.
**지면선 아래에만** 두므로 장애물과 헷갈릴 일이 없다.

### 3.4 리사이즈

`resize`와 `orientationchange`에서 캔버스 크기와 `scale`만 다시 계산한다.
월드 상태(베이컨 위치, 장애물 배열, 카메라 X)는 유닛 기준이라 손댈 필요가 없다.
따라서 **플레이 도중 회전해도 게임이 끊기지 않는다.**

`devicePixelRatio`를 반영해 캔버스 백버퍼를 잡고, CSS 크기는 논리 픽셀로 둔다.

## 5. 스테이지

### 5.1 수치 테이블

난이도는 **두 가지로만** 올라간다 — 스크롤 속도, 그리고 장애물·바굼의 출현 빈도.
장애물의 종류나 크기는 스테이지와 무관하다.

| 스테이지 | 스크롤 속도 | 길이 | 예상 시간 | 장애물 | 바굼 | 장애물 빈도 | 바굼 빈도 |
|---|---|---|---|---|---|---|---|
| 1 | 220 u/s | 16,000u | ~73초 | 8 | 4 | 0.50 /1000u | 0.25 /1000u |
| 2 | 260 u/s | 20,000u | ~77초 | 14 | 7 | 0.70 | 0.35 |
| 3 | 300 u/s | 26,000u | ~87초 | 22 | 11 | 0.85 | 0.42 |
| 4 | 340 u/s | 32,000u | ~94초 | 30 | 15 | 0.94 | 0.47 |
| 5 | 380 u/s | 38,000u | ~100초 | 40 | 20 | 1.05 | 0.53 |

빈도가 올라가고 속도도 붙으므로, **체감 간격**(장애물 하나를 넘고 다음 것이 올 때까지의
시간)은 스테이지 1의 약 7.8초에서 스테이지 5의 약 2.3초까지 줄어든다.
(5.3의 여유 구간을 뺀 실제 배치 구간 기준: 스테이지 1은 13,700u에 8개 → 평균 1,712u,
스테이지 5는 35,700u에 40개 → 평균 892u. 둘 다 최소 간격 규칙을 여유 있게 만족한다.)

### 5.2 장애물 4종

배경 그림에 나온 것 그대로. 크기는 가장 느린 스테이지 1에서도 넘을 수 있도록 역산한 값이다.

| 장애물 | 폭 | 높이 | 생김새 |
|---|---|---|---|
| 덤불 | 60u | 55u | 초록 덤불 |
| 벽돌 기둥 | 45u | 100u | 갈색 벽돌 |
| 토관 | 52u | 110u | 마리오식 초록 관. 입구 테두리가 몸통보다 넓다 |
| 주황 지붕 기둥 | 50u | 120u | 아이 그림 `background.jpg` 의 그것 |
| 침엽수 | 55u | 135u | 3단 사다리꼴 |

**윗면은 평평해야 한다.** 베이컨은 장애물 윗면(`y = -h`)에 착지하는데, 그림이
뾰족하면 꼭짓점 위에 떠 있는 것처럼 보인다. 침엽수는 3단 사다리꼴로, 주황 지붕은
사다리꼴로 그린다. 침엽수 꼭대기 평면은 `0.84 × 55 = 46u`로 베이컨 폭과 같다.

**넘을 수 있음의 근거** — 오토러너에서는 스크롤이 느릴수록 체공 중 이동 거리가 짧아
오히려 넘기 어렵다. 따라서 최악 조건은 *가장 큰 장애물 × 가장 느린 스테이지*다.

침엽수(135u, 폭 55u)를 스테이지 1(220 u/s)에서 넘는 경우:

```
점프 중 높이 135u 이상에 머무는 시간 = 0.524s
그 사이 이동 거리 = 0.524 × 220 = 115u
넘어야 하는 거리 = 장애물 폭 55u + 베이컨 폭 46u = 101u
→ 여유 14u. 통과 가능
```

스테이지 5(380 u/s)에서는 같은 계산이 199u 대 101u로 여유가 크다.

### 5.3 배치 생성 — "스테이지 시작 전에 확정"

스테이지 시작 화면에서 `buildStage(stageNo, seed)`를 **한 번만** 호출해 장애물·바굼
배열을 통째로 확정한다. 플레이 중에는 이 배열이 절대 바뀌지 않는다.
죽어서 되돌아가도, 목숨을 다 써서 스테이지를 처음부터 다시 해도 배치가 동일하다.

- 시드 기반 PRNG(mulberry32 등)를 쓴다. `Math.random()` 직접 호출 금지
- 시드는 `state.stageSeeds[stageNo]`에 보관. 스테이지를 클리어하고 다음에 넘어갈 때만 새로 뽑는다

**배치 규칙** (깰 수 없는 구간이 나오지 않게 강제):

1. 연속한 두 장애물 사이 최소 간격 = `체공거리 × 1.6 + 앞 장애물 폭`
   (체공거리 = 0.83초 × 스크롤 속도. 스테이지 1은 292u, 스테이지 5는 505u)
2. 바굼은 장애물 앞뒤로 최소 `체공거리 × 0.8` 떨어뜨린다
2-1. **바굼끼리는 최소 `체공거리 × 1.2`** 떨어뜨린다. 이것도 속도에 맞춰 늘어나야
   한다 — 고정 거리로 두면 빠른 스테이지에서 바굼 둘이 붙어, 앞 바굼을 뛰어넘어
   착지하는 순간 뒤 바굼에 닿아 죽는 구간이 생긴다. 1보다 크게 잡아 한 번 뛰고
   착지했을 때 다음 바굼까지 여유가 남게 한다
3. 스테이지 시작 후 첫 1,500u와 팩맨 앞 800u는 비워 둔다
4. 장애물 종류는 **모든 스테이지에서 5종을 똑같은 확률(각 20%)로** 뽑는다.
   스테이지가 올라간다고 큰 장애물이 더 나오지는 않는다 — 난이도는 오직
   **스크롤 속도**와 **출현 빈도**로만 올린다 (5.1 참고)

생성 결과는 다음 형태의 배열:

```js
{
  length: 16000,
  speed: 220,
  obstacles: [ { x, kind, w, h }, ... ],   // x 오름차순
  bagooms:   [ { x, patrol }, ... ]        // x 오름차순
}
```

| 스테이지 시작 | 팝업 "스테이지 n / 스테이지 끝까지 도달하세요" — 엔터 또는 클릭으로 시작 |
| 플레이 | 본 게임 |
| 스테이지 결과 | 별 등급 + 점수 내역 (2.3 참고) |
| 최종 엔딩 | 베이컨이 팩맨 입으로 쏙 들어가는 연출, 총점·별 합계, 크레딧. 엔터/클릭 → 인트로 |

## 7. 조작

| 입력 | 동작 |
|---|---|
| 스페이스 / 엔터 / 화면 탭·클릭 | 점프 (플레이 중), 확인 (그 외 화면) |
| 톱니바퀴 아이콘 클릭 | "게임에서 나가시겠습니까?" 팝업 → 예/아니오 |
| 음소거 아이콘 클릭 | 소리 켜기/끄기 |

- 터치는 `touchstart`로 받아 지연을 없앤다. `touchstart`와 `click` 중복 발화 방지
- 아이콘 영역 터치는 점프로 처리하지 않는다
- 나가기 팝업의 기본 선택은 "아니오"
- 팝업이 뜨면 게임은 일시정지

## 9. 사운드

전부 Web Audio API로 실시간 합성. 외부 파일 없음.

| 소리 | 구현 |
|---|---|
| 점프 | 짧은 상승 스윕 (square) |
| 바굼 밟기 | 만화적인 "뾵" — 하강 스윕 + 노이즈 짧게 |
| 피격 / 사망 | 짧은 하강음 |
| 팩맨 도착 | 상승 아르페지오 팬파레 |
| 스테이지 BGM | 칩튠 루프. 스테이지가 올라갈수록 템포 상승 |
| 인트로 BGM | 밝고 느린 멜로디 |

첫 사용자 입력 시점에 `AudioContext`를 resume한다 (모바일 브라우저 자동재생 정책).
음소거 상태는 `localStorage`에 저장한다.

## 11. 테스트

브라우저를 띄우지 않고 `node --test`로 돌린다. "재미있는가"는 사람이 봐야 하지만,
화면을 통째로 죽이는 사고는 전부 여기서 잡는다.

| 대상 | 검증 내용 |
|---|---|
| `physics.js` | AABB 교차, 밟기 vs 측면 충돌 구분, 점프 최고점 224u |
| `bacon.js` | 점프 높이·체공 시간, 가변 점프, 이중 점프 금지, 장애물 윗면 착지, 옆구리 막힘 |
| `stage.js` | 같은 시드 → 같은 배치. 최소 간격 규칙 위반 0건. 개수 일치. 부활 지점이 장애물·바굼에 붙지 않음 |
| `score.js` | 점수 합산, 별 등급 경계값 |
| `render.js` | 6가지 화면비에서 한 프레임이 예외 없이 그려짐. 스프라이트 좌표에 NaN 없음 |
| `scenes.js` | 씬 전환 전체 경로, 회전, 목숨 소진, 봇 완주 |

두 가지는 특별히 못박아 둔다.

**넘을 수 있는가** — 모든 스테이지의 모든 장애물에 대해
`체공 중 이동거리 > 장애물 폭 + 베이컨 폭`을 검사한다. 5.2의 계산이 코드와
어긋나면 바로 깨진다.

**깰 수 있는가** — 장애물을 보고 뛰는 봇에게 다섯 스테이지를 다 맡긴다.
봇이 팩맨에 도착하지 못하면 실패다. 이 테스트가 "바굼 둘이 붙어 있어 앞 바굼을
넘어 착지하는 순간 뒤 바굼에 닿아 죽는" 구간을 찾아냈다 (5.3의 2-1 규칙).

**NaN 검사** — 진짜 캔버스는 NaN 좌표를 받으면 에러 없이 조용히 아무것도 안 그린다.
가짜 컨텍스트가 NaN 인자를 받으면 즉시 예외를 던지게 해 두었다.

사운드와 "보기 좋은가"는 브라우저에서 직접 확인한다.

## 13. 범위에서 뺀 것 (YAGNI)

- 캐릭터 선택 화면 — 주인공은 베이컨 하나
- 최고 기록 / 랭킹 저장 — 음소거 설정만 `localStorage`에 남긴다
- 좌우 이동, 웅크리기, 이중 점프 — 조작은 점프 하나
- 아이템, 파워업, 보스
- 다국어 — 한국어만
